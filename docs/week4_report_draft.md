- 실제 시작 시각: `[직접 입력]`

## 활동 목표

반도체 기술동향 사이트의 정보를 사용자의 관심 직무·기업과 발송 주기에 맞게 이메일로 안전하게 전달하는 구독 자동화 기능을 구축한다. 또한 자동 분류 결과를 사람이 직접 검토하여 공정기술·양산기술과 실제 관련이 낮은 기사가 포함되는 문제를 찾고, 분류 기준과 자동검사를 개선하여 사이트 정보의 직무 적합성과 신뢰도를 높인다.

## 수행내용

먼저 Google Form에 이메일 주소, 신청·해지 요청, 관심 직무, 관심 기업군, 희망 발송 주기와 개인정보 수집·이메일 수신 동의 항목을 구성하고, 응답을 비공개 Google Sheet와 연결하였다. 해지 요청자도 관심 분야와 수신 동의를 다시 선택해야 하는 불편을 직접 발견하여, 이메일과 요청 유형을 먼저 입력한 뒤 신규 신청자는 상세 질문으로 이동하고 해지 요청자는 바로 제출하도록 설문 흐름을 수정하였다. 구독자 이메일은 공개 GitHub 저장소에 저장하지 않고 비공개 Sheet에서만 관리하도록 하였으며, Apps Script에는 본인 한 명 시험 발송, 동일 콘텐츠 중복 차단, 동시 실행 방지, 1회 최대 발송 인원과 계정 발송 한도 확인 기능을 적용하였다. 일간·주간 발송 계획을 먼저 미리 확인한 후 시험 메일 수신과 시간 기반 자동 실행 설정까지 점검하였다.

이후 구독자의 관심 직무와 기업군에 맞는 기사만 선택하도록 개인화 기능을 시험하였다. 이 과정에서 모든 기업을 선택했는데도 관련 기사가 없다고 표시되는 문제와, 설문을 수정하면서 같은 이름의 응답 열이 중복되어 프로그램이 이전 값을 읽는 문제가 발생하였다. 실행 기록에 현재 연결된 스프레드시트명, 응답 시트명, 마지막 행, 발송 주기, 관심 기업, 요청 유형과 동의 상태를 표시하도록 진단 기능을 추가하여 원인을 좁혔다. 그 결과 프로그램이 최신 응답 열이 아닌 과거 열을 읽고 있음을 확인하고, 같은 제목의 열이 여러 개일 때 가장 오른쪽의 최신 값을 사용하도록 수정하였다. 수정 후 구독 신청과 동의 상태가 정상적으로 인식되는 것을 확인하였다. 새 기사가 없을 때는 억지로 메일을 발송하지 않고 `콘텐츠 없음`으로 처리하고, 일간 대상 기사가 부족할 때에는 주간 범위에서 조건에 맞는 기사를 보여주는 보완 방식도 적용하였다.

마지막으로 사이트의 공정기술·양산기술 분류 정확도를 사람이 직접 점검하였다. 기사 5건의 공식 원문을 확인하면서 공정 관련성, 자동 공정 판정, 기술 분야, 관련 직무와 한국어 제목 품질을 항목별로 기록하였다. 검토 결과 High-NA EUV와 하이브리드 본딩처럼 공정·계측·양산과 직접 연결되는 기사는 적절했지만, 산학 협력이나 스마트 글라스 기사처럼 반도체 제조 공정과 직접 관련이 낮은 기사도 일반적인 `process`, `manufacturing` 단어 때문에 공정기술·양산기술로 분류되는 사례가 있음을 발견하였다. 이에 모호한 단어 하나만으로 공정 직무를 부여하지 않고, 반도체 제조·양산·생산능력·노광·식각·증착·계측·검사·본딩 등 명확한 공정 근거가 있을 때만 분류하도록 기준을 수정하였다. 잘못 분류되었던 사례는 제외되고 High-NA EUV, 하이브리드 본딩, 생산능력 확대와 파운드리 공정 기사는 유지되는지 7개의 자동검사로 확인하였다. 이 검사는 매일 뉴스가 갱신되기 전에 자동 실행되도록 GitHub Actions에 연결했으며, 최종 실행이 성공한 것을 확인하였다.

수동 검토를 계속할 때 매번 기사를 직접 골라 표에 옮기는 작업이 비효율적이라고 판단하여 분류 검토표 자동 생성 기능도 만들었다. 최신 기사 중 자동으로 공정 직무가 부여된 기사와 핵심 기사이지만 공정 직무가 부여되지 않은 기사를 절반씩 선정하고, 특정 회사에 치우치지 않도록 회사별로 번갈아 추출하였다. 회사, 게시일, 한·영 제목, 공식 원문 링크, 중요도, 자동 기술 분야와 관련 직무를 미리 입력하고 사람의 평가 칸만 비워 두었다. 시험 결과 8개 기업의 기사 10건이 공정 판정 5건과 비교 대상 5건으로 생성되어, 이후에는 원문을 확인하고 맞음·틀림과 메모만 기록할 수 있게 되었다.

## 성찰내용

이번 활동을 통해 자동화 기능은 코드가 오류 없이 실행되는 것만으로 완성되는 것이 아니라, 실제 사용자의 입력이 어떻게 저장되고 어떤 조건에서 발송되는지 끝까지 확인해야 한다는 점을 배웠다. 처음에는 모든 기업을 선택했는데도 기사가 없다는 결과가 나와 기사 필터가 잘못되었다고 생각했지만, 실행 기록을 단계별로 확인한 결과 설문 수정 과정에서 중복된 열이 생기고 프로그램이 과거 값을 읽는 것이 원인이었다. 화면에 보이는 결과만 추측하지 않고 입력값, 처리 과정, 최종 결과를 차례로 확인하는 것이 문제 해결의 기본임을 이해하였다. 또한 새 기사가 없을 때는 빈 메일이나 관련 없는 기사를 보내는 것보다 발송하지 않는 판단이 사용자에게 더 안전하다고 느꼈다.

기사 분류 검토에서는 자동으로 직무명이 붙었다고 해서 의미상 정확한 것은 아니라는 점을 다시 확인하였다. 일반적인 단어가 포함됐다는 이유만으로 산학 협력이나 소비자 제품 기사를 공정기술 기사로 판단하면 취업 준비생에게 잘못된 신호를 줄 수 있었다. 직접 공식 원문을 읽고 결과를 표로 비교하면서, 공정기술·양산기술은 반도체 제조 단계, 공정 조건, 설비, 계측·검사, 생산능력과 같은 구체적인 근거가 있을 때만 연결해야 한다고 판단하였다. AI는 코드 초안 작성과 오류 원인 후보 제시를 도왔지만, 어떤 분류가 직무상 타당한지 결정하고 오분류 사례를 선정하며 수정 결과를 승인한 것은 사람의 역할이었다. 앞으로도 AI가 만든 결과를 그대로 받아들이기보다 소수 사례를 직접 검토하고, 발견한 오류를 자동검사로 바꾸어 같은 문제가 반복되지 않도록 개선하고자 한다.

## AI 활용 경험

이번 주에는 AI를 단순히 답변이나 코드를 만들어 주는 도구로 사용하지 않고, 문제를 찾고 검증 기준을 만드는 보조 도구로 활용하였다. AI가 제안한 코드는 바로 전체 구독자에게 적용하지 않고 발송 계획 확인, 본인 한 명 시험, 중복 차단 확인 순서로 범위를 넓혔다. 오류가 발생했을 때도 AI의 설명을 그대로 믿지 않고 Apps Script 실행 기록과 실제 Sheet 값을 비교하여 원인을 확인하였다. 기사 분류에서는 사람이 직접 작성한 평가표를 기준으로 AI와 규칙의 결과를 검토하고, 잘못된 사례와 올바른 사례를 자동검사로 만들었다. 이를 통해 AI 활용 능력은 명령을 복사하는 것이 아니라 목표와 허용 기준을 정하고, 결과를 검증하며, 실패를 다음 검사 기준으로 바꾸는 능력이라는 점을 이해하였다.
