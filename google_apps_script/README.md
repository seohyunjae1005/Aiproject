# Google Apps Script 맞춤 이메일 발송

Google Form 응답 Sheet 안에서 실행한다. GitHub에는 구독자 이메일과 발송 기록을 올리지 않는다.

## 안전 원칙

- 같은 이메일은 가장 최근에 제출한 신청 또는 해지 상태만 사용한다.
- `신규 구독 신청`이고 수신에 동의한 사람만 발송 대상이 된다.
- 일간 신청자와 주간 신청자를 분리한다.
- 관심 직무와 관심 기업군이 일치하는 기사를 우선 배치한다.
- 맞춤 기사가 없으면 공정·양산기술 관련 핵심 기사만 대체 제공한다.
- 맞춤 기사와 공정·양산 대체 기사도 없으면 이메일을 보내지 않는다.
- 같은 구독자에게 같은 리포트를 두 번 보내지 않는다.
- `발송 기록` 시트에는 이메일 원문 대신 SHA-256 해시만 저장한다.
- 새 기사가 없는 리포트는 발송하지 않는다.
- 동시에 두 발송이 실행되지 않도록 잠금을 사용한다.
- 한 번에 최대 20명까지만 발송하며 Google 계정의 남은 일일 한도를 넘지 않는다.
- 기본값 `LIVE_SEND_ENABLED = false`에서는 다중 발송이 차단된다.

## 1. 코드 업데이트

1. 응답 Sheet에서 `확장 프로그램 → Apps Script`를 연다.
2. 기존 `Code.gs` 전체를 저장소의 최신 `google_apps_script/Code.gs` 내용으로 교체한다.
3. 저장한다.

## 2. 발송 없이 개인화 확인

먼저 함수 목록에서 `previewLatestSubscriberPersonalization`을 실행한다. 가장 최근의 유효한 구독 신청 1건을 기준으로 아래 항목만 로그에 표시하며 이메일은 보내지 않는다.

- 일간 또는 주간 발송 주기
- 선택 조건에 맞는 기사 수
- 관심 분야 기사가 없어 공정·양산 핵심 기사로 대체했는지 여부

폼의 질문 제목은 `관심직무` 또는 `관심 직무`, `관심 기업군` 또는 `관심기업군`을 모두 인식한다.

## 3. 전체 발송 계획 확인

1. 함수 목록에서 `previewDeliveryPlan`을 선택한다.
2. `실행`을 누른다.
3. 실행 로그에서 일간·주간별 `승인`, `중복 제외`, `콘텐츠 없음`, `발송 예정` 인원을 확인한다.

이 함수는 이메일을 보내지 않으며 `발송 기록` 시트도 만들지 않는다.

## 4. 한 사람 맞춤 시험 발송

1. 본인 이메일의 가장 최근 응답을 `신규 구독 신청` 상태로 둔다.
2. 함수 목록에서 `sendTestToLatestSubscriber`를 선택해 실행한다.
3. 제목에 `[테스트] [반도체 맞춤 브리프]`가 표시되는지 확인한다.
4. 관심 직무·기업 기준, 기사 수, 원문·대시보드·해지 링크가 정상인지 확인한다.
5. 관심 분야 기사가 없을 때 공정·양산 대체 안내가 표시되는지 확인한다.

시험 발송은 실제 발송 기록에 포함하지 않는다.

## 5. 실제 발송 전 마지막 잠금

다중 발송을 검증하기 전에는 아래 값을 그대로 둔다.

```javascript
const LIVE_SEND_ENABLED = false;
```

`sendDailyDigest` 또는 `sendWeeklyDigest`를 잘못 실행해도 메일은 발송되지 않는다. 대상 수와 시험 메일까지 확인한 뒤에만 `true`로 변경한다.

## 6. 실제 발송 함수

- `sendDailyDigest`: 일간 신청자에게 새 기사 일일 요약 발송
- `sendWeeklyDigest`: 주간 신청자에게 주 1회 요약 발송

성공한 발송은 비공개 Google Sheet의 `발송 기록` 탭에 기록된다. 구독자의 관심 조건과 포함 기사 URL을 이용해 콘텐츠 키를 만들므로, 같은 맞춤 콘텐츠로 함수를 다시 실행하면 중복 발송을 건너뛴다. 관심 조건을 바꾸거나 포함 기사가 바뀌면 새로운 콘텐츠로 판단한다.

예약 실행 트리거는 실제 발송 검증이 끝난 뒤 설정한다.
