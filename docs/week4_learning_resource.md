# 4주차 학습자료 — 산업 동향 집계와 공정 직무 리포트

## 1. 이번 주차는 어떤 단계인가

1~2주차에는 공식 기사를 모아 분류·번역했고, 3주차에는 개별 기사에 AI 직무 분석을 붙였다. 4주차는 여러 기사를 한꺼번에 묶어 **최근 산업 흐름을 비교하는 단계**이다.

```text
공식 기사 여러 건
  → 날짜·기업·기술·직무별 집계
  → 최근 기간과 이전 기간 비교
  → 증가한 신호 확인
  → 공정기술·양산기술 중심 AI 리포트
  → 근거 번호 검사 후 웹사이트 공개
```

개별 기사 분석이 나무 한 그루를 보는 일이라면, 산업 동향 분석은 숲의 변화를 보는 일에 가깝다.

## 2. 꼭 알아야 할 개념

### 집계

집계는 여러 기사를 공통 기준으로 묶어 개수를 계산하는 것이다. 이 프로젝트에서는 기간, 기업, 기술 분야와 관련 직무를 기준으로 묶었다.

- 최근 7일: 아주 최근에 나온 신호
- 최근 30일: 한 달 흐름
- 최근 90일: 더 긴 기간의 배경

기간이 길어질수록 포함하는 날짜가 많으므로 기사 수가 줄어들면 계산 오류일 가능성이 있다. 핵심 기술 기사는 전체 기사 중 일부이므로 핵심 기사 수가 전체 기사 수보다 많아서도 안 된다.

### 비교 기준선

최근 30일 기사 수가 7건이라는 숫자만으로는 증가했는지 알 수 없다. 그래서 길이가 같은 직전 30일과 비교하였다.

```text
최근 30일 7건 - 직전 30일 2건 = 5건 증가
```

이 차이는 공식 발표가 늘었다는 신호이지, 시장 규모가 정확히 그만큼 커졌다는 뜻은 아니다.

### 기사 건수와 기술 중요도의 차이

기사 건수는 회사의 공식 발표 빈도를 나타낸다. 다음과 같은 값과 동일하지 않다.

- 시장점유율
- 실제 투자액
- 제품 판매량
- 수율 향상 정도
- 기술의 절대적 중요도

따라서 화면과 AI 결과에서 `공식 발표 빈도이며 시장 전체를 대표하지 않는다`는 한계를 함께 표시하였다.

### 근거 ID

AI가 그럴듯한 결론을 임의로 만드는 것을 줄이기 위해 입력 자료에 번호를 붙였다.

- `M1`, `M2` 등: 기간별 통계와 증가 신호
- `A1`, `A2` 등: 공식 기사 제목

AI가 작성한 핵심 변화에는 실제 M번호를, 기업 관찰에는 실제 A번호를 반드시 사용하게 하였다. 존재하지 않는 번호를 사용하면 게시하지 않는다. 이 구조 덕분에 사용자는 AI 문장에서 원래 통계와 기사로 돌아갈 수 있다.

### 캐시와 API 비용

같은 통계로 월간 리포트를 다시 만들 때 AI를 매번 호출할 필요가 없다. 통계와 기사 입력이 같으면 기존 결과를 재사용하고, 입력이 바뀌었을 때만 새로 분석한다. 이것이 캐시이며 비용과 실행시간을 줄인다.

## 3. 공정기술·양산기술 관점으로 읽는 방법

기술 이름을 외우는 데서 끝내지 않고 다음 질문으로 연결해야 한다.

### 미세 선폭과 High-NA EUV

- 미세한 패턴이 목표 크기로 형성되었는가?
- 노광 조건 변화가 공정 변동에 어떤 영향을 주는가?
- overlay와 critical dimension을 어떤 계측 장비로 확인하는가?
- 연구 조건을 대량생산에 적용할 때 균일도와 설비 안정성 문제는 없는가?

### 계측·검사

- 결함을 어느 공정 단계에서 가장 빨리 찾을 수 있는가?
- 검사 정확도를 높이면 처리시간이나 생산량에 어떤 영향이 있는가?
- 이상 신호를 공정 조건, 장비 상태와 어떻게 연결할 수 있는가?

### 하이브리드 본딩과 첨단 패키징

- 두 표면을 붙이기 전에 평탄도와 오염을 어떻게 관리하는가?
- 정렬 오차가 연결 불량과 수율에 어떤 영향을 주는가?
- 열과 기계적 응력이 신뢰성에 어떤 영향을 주는가?
- 전공정과 패키징 공정의 데이터를 어떻게 이어서 원인을 찾는가?

공정 엔지니어에게 중요한 것은 `새 기술이 중요하다`는 문장이 아니라, 기술 도입 시 관리해야 할 공정 변수·계측 항목·설비 조건·불량 위험을 질문하는 것이다.

## 4. 이번 주차에서 사용한 코드의 역할

| 구성요소 | 쉬운 설명 |
| --- | --- |
| 기간별 집계 코드 | 기사 날짜를 보고 7·30·90일 묶음으로 계산한다. |
| 증가 신호 계산 | 최근 30일과 직전 30일의 차이를 계산한다. |
| 기업별 프로필 | 회사별 핵심 기술과 관련 직무를 다시 묶는다. |
| AI 월간 리포트 | 검증된 통계와 기사 제목을 직무 관점으로 해석한다. |
| 품질검사 | 기간별 숫자 관계와 AI 근거 번호를 확인한다. |
| GitHub Actions | 월간 리포트 생성과 검사를 자동 실행한다. |

## 5. AI가 한 일과 내가 한 일

### AI가 도운 부분

- 집계·웹 표시·품질검사 코드의 초안 작성
- 오류 메시지의 원인 설명
- 검증된 통계와 기사 제목을 바탕으로 한 리포트 문장 생성
- 보고서 문장의 구조 정리

### 내가 판단한 부분

- 7일·30일·90일 기간을 사용할지 결정
- 최근 30일과 직전 30일을 같은 길이로 비교
- 공정기술·양산기술을 첫 번째 직무 관점으로 고정
- 기사 수를 시장 중요도로 표현하지 않도록 제한
- 수율·공정 조건을 근거 없이 만들지 못하도록 규칙 설정
- 통계와 기사 번호가 맞는지 검증 결과 확인

이처럼 AI 활용 역량은 코드를 전부 외워 작성하는 것만 의미하지 않는다. 문제의 기준을 정하고, 결과가 틀릴 수 있는 조건을 찾아 검증하는 것도 중요한 역량이다.

## 6. 직접 설명해 볼 문장

> 4주차에는 개별 기사를 단순 요약하지 않고 날짜·기업·기술·직무별로 집계하였다. 최근 30일과 직전 30일을 비교해 증가 신호를 만들고, AI에는 검증된 통계와 공식 기사 제목만 제공하였다. AI 문장에는 실제 M·A 근거 번호를 요구하고 존재하지 않는 번호가 있으면 게시하지 않았다.

## 7. 복습 실습

1. 사이트에서 최근 7일·30일·90일 기사 수를 찾아 기간이 길수록 감소하지 않는지 확인한다.
2. 최근 30일과 직전 30일의 공정기술·양산기술 기사 수를 비교한다.
3. 기사 증가가 기술 중요도 증가와 같은 뜻이 아닌 이유를 두 문장으로 적는다.
4. 월간 AI 리포트의 M번호와 A번호 하나씩을 실제 통계·기사와 대조한다.
5. High-NA EUV 또는 하이브리드 본딩을 공정 조건, 계측·검사, 수율 위험과 연결해 설명한다.

## 8. 자가점검

- 집계와 개별 기사 분석의 차이를 설명할 수 있는가?
- 최근 30일과 직전 30일을 비교하는 이유를 설명할 수 있는가?
- 기사 건수를 시장 규모로 해석하면 안 되는 이유를 알고 있는가?
- M번호와 A번호가 어떤 근거인지 말할 수 있는가?
- 공정기술 관점에서 기술동향을 어떤 질문으로 읽어야 하는가?

다섯 질문에 답할 수 있으면 4주차의 핵심 구조를 이해한 것이다.
